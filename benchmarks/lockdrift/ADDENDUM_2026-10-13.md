# Addendum C, 2026-10-13 (IST), to the lockfile-update protocol

`SELECTION_PROTOCOL.md` is unchanged. After the 40 candidates were logged, the first
endpoint environments failed to install for all four candidates attempted. **No test had
run in any environment.** The cause was a defect in the frozen lockfile reader
(`regressleuth.lockfiles`), not in the projects.

**Defect.** For `uv.lock` and `poetry.lock`, the reader took every registry package,
ignoring Python-version and platform markers. Universal lockfiles hold several versions of
one package for different Pythons and platform-only packages, so it installed, for
example, numpy 2.5.3 (Python >= 3.12) into a Python 3.11 environment, and `pywin32`
on Linux.

**Fix.** `uv.lock` is now walked from its workspace members, with all extras and
dependency groups, along edges whose markers hold for the target Python and platform.
`poetry.lock` packages are filtered by their `markers` and `python-versions`, and
extras-only packages are left out. A lockfile that still names several versions, or a
package from a non-registry source (git, URL), is reported as an error rather than
guessed. The requirements reader was already marker-aware and is unchanged.
`FREEZE_MANIFEST.v0.json` keeps the hashes frozen before the search;
`FREEZE_MANIFEST.json` was regenerated after this fix and is the one evaluation checks.

**Re-screening.** All 40 candidates were screened again with the corrected reader, at each
candidate's CI Python (3.12 where none is determined). No screening decision changed.
- Every `search_space_above_cap` exclusion is still above 12.
- Five lockfiles of already excluded candidates (four dify-family forks and Chemclaw3#580)
  now fail to read because they take a package from git. They stay excluded for their
  original reasons.
- The eligible drl-cox transitions shrink at Python 3.11: #59 from 6 to 4 components
  (the numpy and scipy changes applied only to Python >= 3.12), and #60 from 8 to 6.

Incident folders prepared with the defective reader were rebuilt by `prepare`, which
overwrites them; no test results existed to discard.
